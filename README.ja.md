# jsa-park — 重いセッションを、離席の前に停めておく

大量のコンテキストを使った Claude Code のセッションを1時間以上放置
すると、プロンプトキャッシュが失効します。戻って一言打った瞬間、
過去の会話全体がキャッシュに登録し直され、重いセッションでは1ターンで
数十万トークンを消費することがあります。

**jsa-park は、この「長い離席」を「安い再出発」に変えるための
Claude Code スキル2本組です。** 離席前にセッションを停め（park）、
新しいセッションでわずかなトークンで再開（resume）します。

| スキル | いつ | 何をするか |
|---|---|---|
| **`jsa-park`** | 離席の前 | 引き継ぎメモ `RESUME.md` を書き出す。記入欄（決まったこと・保留中の提案・次にやること）まで、生きている会話からドラフトする |
| **`jsa-resume`** | 離席の後 | 新しいセッションで「再開します」と言うだけ。`RESUME.md` を読み、「決まったこと」と「保留中の提案」を区別して報告し、**パークで何トークン節約できたかを表示**して、GOが出るまで作業しない |

[English README](README.md)

## インストール

```bash
git clone https://github.com/kansokusha2026/jsa-park.git
cd jsa-park
mkdir -p ~/.claude/skills && cp -r skills/jsa-park skills/jsa-resume ~/.claude/skills/
```

新しいセッションから自動的に有効になります。外すときは
`~/.claude/skills/` から2つのフォルダを削除してください。

## `jsa-park` の動き方

`/jsa-park` で発動するか、「離席します」と伝えるだけでも動きます。

1. **損益分岐の判定。** 1時間以内に戻るなら、キャッシュは生きている
   ことが多く、パークは通常不要です — スキルはそう伝えて止まります。
   それより長い離席、就寝、利用上限での停止なら先へ進みます。
2. **ドラフト。** メモは2部構成です。操作の記録（タスク・変更した
   ファイル・現在地）と、判断の記入欄。「決まったこと」に入るのは
   **あなたが明示的に承認したものだけ**で、それぞれに承認発言の
   手がかりを添えます。承認が特定できないものは、すべて「保留中の
   提案」に落とします。
3. **確認は一点だけ。** 「決まったこと」の中に、実はまだ提案のままの
   ものが混ざっていないか — これだけ確認します。
4. **解放。** メモを保存し（既存の `RESUME.md` は `RESUME.md.bak` に
   退避）、セッションを閉じてよい状態になります。

## `jsa-resume` の動き方

同じフォルダで新しいセッションを開き、**「再開します」**と言うだけです
（`/jsa-resume` でも可）。スキルは `RESUME.md` を探して日付を確認し、
目的・決まったこと・保留中の提案・次にやること を報告し、節約メーター
を表示します。そして**あなたがGOを出すまで作業を始めません。**
「保留中の提案」を確定事項として扱うことは決してありません。この方式
なら、過去の会話全体を登録し直す代わりに、数千トークンで再開できます。

再開セッションは合図の一言から始まるため、タイトルが「再開」のままに
なりがちです。セッション管理ツールがある環境（Claude Code デスクトップ
アプリ）では、ひとつ前のパーク済みセッションを元のタイトル＋連番
（「X」→「X(2)」→「X(3)」）にリネームして系譜を引き継ぎます（セッション
は自分自身をリネームできないため、一歩遅れの自己修復方式です）。CLI
環境ではこの処理は黙ってスキップされます。

## 節約メーター

見えない節約は、習慣として続きません。そこでこのスキルは、パークと
再開のたびに効果を実測して表示します。

- `jsa-park` は、パークするセッションの最終コンテキストサイズを
  `RESUME.md` にスタンプします。読むのは `~/.claude/projects/` の
  ローカル記録だけで、標準ライブラリのみ・外部送信はありません。
- `jsa-resume` は、そのスタンプと新セッションの実際のコールドスタート
  を突き合わせ、差分を毎回報告します。

実例（この機能を実装したセッションそのものの実測値）：

```
=== jsa-park savings meter ===
parked session : 6297ec16  context 160,011 tokens after 77 requests (2026-08-12 08:47)
fresh session  : 96bd6731  cold start registered 78,680 tokens
context shed   : 81,331 tokens (-51%) — conversation history replaced by the handoff note
estimated savings (rate weights: 1h-cache write x2.0, cache read x0.1):
  per cold restart after a 1h+ break : ~162,662 input-token eq avoided
  per message from now on            : ~8,133 input-token eq lighter (vs. continuing the old session)
```

約8.1万トークンの会話履歴が、約1,500トークンの引き継ぎメモに置き換わり
ました。残っているのは主にセッション固定費（システムプロンプト・
ツール定義・プロジェクト設定）で、これはどのセッションでも必ず払う分
です。推定値はモデル非依存のレート比（1時間キャッシュ書き込み≒基本
入力の約2倍、キャッシュ読み≒約0.1倍）で計算しており、価格は仮定して
いないため、どの Claude モデルでも成り立ちます。

## JSA との関係

[JSA](https://github.com/kansokusha2026/jsa) は測定の側です。ローカルの
Claude Code の記録を読む、独立した Python スクリプト3本で構成されて
います。

- **まず測ってください。** JSA の `jsa_gaps.py` を実行すると、再開時の
  消費が実際にあなたに起きているかが分かります。判定が「引き継ぎを
  導入する価値あり」なら、その流れを自動化するのがこのスキルです。
- **同じメモを、逆方向から。** JSA の `jsa_handoff.py` は、セッションが
  終わった*後*に記録からメモを組み立てます — 記入欄は空欄のままです。
  記録に残るのは操作であって、判断ではないからです。`jsa-park` スキルは
  生きているセッションの*内側*で動くため、まだ文脈に残っている判断まで
  ドラフトできます。一行で言えば、**CLI は死んだセッションから操作を
  拾い、スキルは生きているセッションから判断を書き取ります。**
- 離席が事前に分かっているときは `jsa-park` を。セッションがすでに
  失われているとき（利用上限・クラッシュ・ウィンドウを閉じた後）は
  `jsa_handoff.py` を。2つのメモは互換で、`jsa-resume` はどちらも
  読めます。

## 注意

- どちらのスキルも、キャッシュを温存し続けるものではありません。
  タイマーでセッションに送信し続ける方法は、その送信自体が課金される
  ため節約になりません。節約は「古い会話を新しいセッションに持ち込ま
  ない」ことから生まれます。
- スキルを入れると、トリガー用の説明文が全セッションの固定費に
  乗ります。2本で1,000トークンに満たない量ですが、使う頻度が低い
  場合は差し引きを考えてください。
- `RESUME.md` はプロジェクトのルートにできるため、**誤って Git に
  コミットしやすいファイルです。**`.gitignore` に `RESUME.md` と
  `RESUME.md.bak` を追加してください。
- メモには作業内容やファイルパスが入り、認証情報や内部URLが混ざる
  ことがあります。共有する前に必ず中身を確認してください。
- `/compact` `/clear` `/resume` の置き換えではありません。公式機能も
  試し、最適な方法を選択してください。
